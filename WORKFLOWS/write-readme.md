# WORKFLOW: WRITE README

Usa este workflow cuando el usuario quiera crear o rehacer un README de calidad.

## Objetivo

Producir un README claro, útil y realista que explique el proyecto y reduzca fricción de onboarding.

## Secuencia de trabajo

### 1. Identificar el tipo de proyecto
Aclara si se trata de:
- app;
- librería;
- plantilla;
- repositorio de prompts;
- documentación;
- scripts;
- herramienta interna.

### 2. Determinar el público
Identifica si el README está orientado a:
- uso personal;
- colaboradores;
- clientes internos;
- comunidad abierta;
- equipo técnico.

### 3. Recoger la información mínima
Obtén o deduce:
- qué hace el proyecto;
- para qué sirve;
- cómo se usa;
- cómo se instala;
- qué estructura tiene;
- qué estado de madurez tiene.

### 4. Diseñar estructura
Como mínimo, incluye cuando aplique:
- título;
- descripción;
- objetivo;
- estructura;
- instalación;
- uso;
- ejemplos;
- estado actual;
- roadmap;
- licencia.

### 5. Redactar
El README debe ser:
- específico;
- breve cuando se pueda;
- completo cuando haga falta;
- honesto sobre límites;
- fácil de escanear.

### 6. Validar
Comprueba:
- que no hay secciones vacías disfrazadas;
- que los ejemplos son plausibles;
- que el onboarding es accionable;
- que no promete lo que el proyecto no hace.

## Formato de salida recomendado

README completo, listo para copiar y pegar.
